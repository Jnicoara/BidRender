## Why

A batch of marks resent after a lost answer used to count twice (3 → 6).
Tonight's live candidate closes it IN MEMORY (`server/markReplay.ts`: one
server, a day). That map is empty after a restart, is not shared between
instances, and is read before either of two racing sends writes — so a
resend racing its own first send still counts twice. **Measured on the
candidate `448d1281`:** two sends of one 3-mark batch at once → 6 marks
(`server/markReplay.test.ts`, "two sends … AT ONCE": 11 where 8 is right).
